## 为什么做 VQD

普通回测很擅长回答一个问题：

**这套策略过去赚了多少钱？**

但真正做研究时，还会有更多问题：

**为什么会赚？当时到底看到了什么数据？结果从什么时候开始失效？换一个时间窗口以后还成立吗？这个策略是怎么一步步从研究想法变成最终交易决策的？**

Visual Quant Debugger（VQD）就是围绕这些问题做的。

在 VQD 里，回测不是终点。每一个策略想法都应该留下完整的研究记录：使用的数据版本、因子证据、验证边界、留出集、组合来源、策略版本、运行记录、Trace 和最终结果。

VQD 的目标不是自动帮你找到历史 Sharpe 最高的策略。

它更关注的是让量化研究**看得懂、查得到、能回放，并且尽量减少自己骗自己的空间**。

## VQD 能做什么

VQD 把一套完整的量化研究流程放在同一个工作台里：

```text
市场数据
    ↓
因子研究
    ↓
验证 / 留出集
    ↓
多因子组合
    ↓
滚动前向稳定性
    ↓
因子关系
    ↓
研究假设
    ↓
原生策略
    ↓
回测
    ↓
Trace / 回放
    ↓
诊断 / 盈亏解剖
    ↓
前向验证
    ↓
虚拟盘
```

每一步都会保留进入下一步所需要的证据和研究链路。

## 主要功能

### 历史市场

使用真实美股历史数据或自己导入的数据集，并按照指定历史日期查看当时可知的市场信息。

VQD 会把数据版本、时间戳、股票池信息和当时可用的基本面记录一起保存，而不是把数据当成一个看不见的输入。

### 因子实验室

研究价格 / 成交量因子、基本面因子、混合因子和自定义因子。

可以查看 IC、Rank IC、分位收益、Q5-Q1、覆盖率、换手率，并按照研究集、验证集、留出集逐步揭示证据。

留出集不会被系统偷偷拿来调参数。

### 组合实验室

把已经完成的因子研究组合成一个透明的多因子投资组合。

你可以明确设置：

- 使用哪些因子；
- 因子方向和权重；
- 组合与排序方式；
- 股票池和筛选条件；
- Top N / Top %；
- 持仓权重方式；
- 单一持仓上限；
- 日 / 周 / 月调仓。

每一个最终持仓都可以追溯回对应的因子证据。

VQD 不需要用隐藏优化器替你寻找“最佳权重”。

### 滚动前向验证

检查一个研究想法随着时间向前推进以后是否仍然稳定。

VQD 会把固定的研究定义放进连续的研究、验证和前向窗口中，并记录因子或策略第一次出现明显退化的位置。

### 因子关系

判断两个看起来不同的因子是不是其实在表达同一类信息。

可以比较：

- 因子值相关性；
- 因子排名相关性；
- 因子收益相关性；
- 滚动相关性；
- Top 分位组合重叠；
- Jaccard；
- 冗余度；
- 增量信息；
- 因子聚类。

VQD 只展示关联和重叠证据，不会因为相关性高就自动删除因子或重新优化组合。

### 策略发现

从已有研究证据出发，形成一个明确的研究假设。

一个 Hypothesis 会保存：

- 来自哪些因子；
- 支持证据；
- 反对证据；
- 预期关系和持有周期；
- Validation / Holdout 状态；
- 历史修订版本；
- Portfolio 和 Strategy 来源；
- 最终产生的 Run 和 Trace。

如果你在看到新的验证结果以后修改想法，VQD 会创建新的 Revision，而不是直接覆盖旧实验。

### 研究快照

把一条已经完成的研究链路冻结成不可变、内容可校验的记录。

一个 Research Snapshot 会保存精确的 Dataset 修订、Factor 与 Strategy 修订、参数、Research / Validation / Holdout 时间边界、Hypothesis、Portfolio、Run、Trace 以及创建环境。每项冻结制品都有独立的源修订和载荷哈希，因此源记录后续发生变化也不会悄悄改写已经保存的实验。

研究快照只允许追加。不同实验会创建新的身份，不会更新已有 Snapshot。

在 **实验对比** 中选择两到四个快照，可以并排检查受控上下文、制品修订、参数变化、冻结的 Portfolio 与主要 Run 结果、Hypothesis 证据状态，以及已经记录的 Run / Trace 行为。对比只读取通过内容校验的冻结载荷，并复用 Run Comparison 契约；它只描述差异，不会选出赢家、优化参数或给出推荐。

### 回放

把已经完成的策略运行一根 K 线一根 K 线重新打开。

你可以查看某个时点的：

- 市场快照；
- 特征值；
- 判断条件；
- 目标仓位；
- 成交；
- 手续费和滑点；
- 盈亏；
- 当时真正可用的数据依赖。

这也是 VQD 和普通回测工具差别最大的一部分：**策略不再只有一条权益曲线，而是可以像程序一样被调试。**

### 诊断

围绕同一条已经保存的 Run 做压力检查，而不丢失原始上下文。

包括：

- 时间顺序 Train / Test；
- 可交互的参数敏感性；
- 交易成本压力；
- 执行延迟；
- 确定性的诊断结论。

### 盈亏解剖

不只看最终收益率，而是继续追问盈亏从哪里来。

可以把毛盈亏、手续费、滑点、具体交易、未平仓交易和回撤阶段重新对应到底层策略事件。

### 前向验证与虚拟盘

让策略离开一次性的历史批量回测。

VQD 支持逐步揭示历史数据的前向验证、持久化虚拟账户、真实 Alpaca 行情，以及可选的 Alpaca Paper 模拟券商成交。

真实资金交易不在 VQD 的产品范围内。

## VQD 和普通回测工具有什么不同

### 先看证据，再看结论

VQD 同时保存支持和反对一个想法的证据，不会因为某一个历史指标很好看就自动把它定义成“好策略”。

### Point-in-Time

系统会记录数据什么时候变得可用、什么时候被策略使用。

研究、验证和前向收益的时间边界会被明确限制，减少未来信息泄漏进过去研究的风险。

### Holdout 必须主动揭示

留出集默认保持封闭。

VQD 不会自动拿 Holdout 去搜索参数，也不会自动用它挑选赢家。

### 完整研究链路

一个最终结果可以一路追溯：

```text
Dataset
→ Factor
→ Factor Research
→ Portfolio
→ Hypothesis
→ Strategy
→ Run
→ Trace
```

### 运行过程可以调试

一条 Run 不只是收益曲线。

VQD 会记录特征、判断、仓位、订单、成交、成本和盈亏，因此以后可以重新回放它到底为什么做出了某次交易。

### 不是自动找赢家的机器

VQD 不是“AI 自动发现 Alpha”的产品。

它不会自动大规模搜索参数、寻找最佳窗口、提前查看 Holdout、挑选历史赢家，也不会自动部署真钱策略。

所有量化结果来自后端确定性计算。即使接入 AI，AI 也只适合解释已经揭示的研究证据，而不是替代 Quant Engine。

## 研究记录不是一次性结果

VQD 会持久保存回测、因子研究、组合、Hypothesis、Trace、诊断和虚拟盘记录。

因此过一段时间回来，你仍然可以回答：

- 这个结果到底用了哪一版数据？
- 用的是哪一版因子？
- 两次运行到底改了什么？
- 行为第一次从哪里开始不同？
- 这个想法有没有通过 Validation 和 Holdout？
- 这笔交易发生时，策略当时知道什么？
- 手续费、滑点和执行时点吃掉了多少结果？

这些问题不应该依赖人的记忆或几张截图。

**https://visual-quant-debugger-production.up.railway.app**

## 本地运行

最简单的方式是 Docker：

```bash
git clone https://github.com/LIRuixuan0407/Visual-Quant-Debugger.git
cd Visual-Quant-Debugger
docker compose up --build
```

然后打开：

```text
http://localhost:8000
```

VQD 的本地持久化研究数据保存在 `.vqd` 工作区中；容器部署默认把持久化工作区挂载到 `/data`。

如果需要真实 Alpaca 行情或 SEC 财务披露，可以参考 `.env.example` 配置可选的数据提供方参数。

## 自定义策略和因子

VQD 提供原生 Strategy SDK 和 Factor SDK，用于加载可信的本地 Python 研究代码。

自定义 Factor 可以和内置 Factor 一样继续进入：

```text
Factor Research
→ Validation
→ Portfolio
→ Walk-Forward
→ Factor Relationships
→ Strategy Discovery
→ Research Snapshot
```

自定义原生 Strategy 也可以继续进入：

```text
Backtest
→ Trace
→ Replay
→ Diagnose
→ P&L Autopsy
→ Forward
→ Paper
```

同时提供可选的 `backtesting.py` 和 `vectorbt` 历史研究适配器，并明确展示不同运行方式能够提供的 Trace 完整度。

## 产品原则

VQD 有几条比较严格的原则：

- 前端只展示量化结果，不重新计算 Quant 指标；
- Research 和真正执行的 Strategy 应保持相同语义；
- 没有证据的数据就显示“不可用”，而不是猜一个结果；
- Holdout 必须显式揭示；
- 修改研究想法要保留旧 Revision；
- 亏损和失败的 Hypothesis 也是有效研究结果；
- 不做真实资金交易。

## 当前范围

VQD 目前是一个持续开发中的开源个人量化研究工作台。

当前产品已经覆盖历史市场、因子研究、多因子组合、滚动前向验证、因子关系、基于证据的策略发现、不可变研究快照、回测、回放、诊断、盈亏归因、前向验证和虚拟盘。

它应该被当作研究软件，而不是投资建议，也不代表任何策略未来能够盈利。
